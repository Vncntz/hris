## Goal and scope

Generate a small, read-only context packet for one explicitly named TASK. The packet routes an agent to the linked IMP, required governance, and selected frozen decisions with source identity and hashes. It reduces repeated document discovery while leaving the source files and human or agent review authoritative.

Affected paths: a new `tools/task-context.py`, focused `tools/tests/test_task_context.py`, `docs/tasks/TASK-0020.context.json` as the first adjacent routing manifest, and minimal `AGENTS.md` / documentation-index guidance. No HRIS product code, migrations, frozen planning source, CI platform coverage, remote governance setting, or permission change is in scope.

## Acceptance criteria

1. The CLI accepts one exact `TASK-####` ID, uses a validated adjacent routing manifest when present, and permits explicit `D-###` IDs for tasks without a manifest or additional targeted retrieval. TASK-0020 has the first manifest. It never chooses a task, authorizes implementation, or declares a gate passed. A missing, inconsistent, duplicated, or malformed TASK/IMP identity fails closed with no partial packet.
2. Each emitted task, IMP, governance, routing, and decision reference identifies its repository-relative source, line range where applicable, byte count, and SHA-256 content digest. The packet carries Git HEAD, branch, and dirty-worktree status and a clear non-authoritative notice. It includes task/IMP text and only requested decision excerpts, not entire frozen planning sources or CI logs.
3. Decision excerpts come from the existing indexed `plan-get.py`; unknown IDs, stale index ranges or hashes, mismatched excerpt identities, and missing sources fail closed. The tool does not execute code from an arbitrary `--repo` input or from a PR checkout during trusted-main integration.
4. Optional routing metadata is checked against the actual task identity and linked IMP, uses only repository-contained paths, and cannot silently expand scope or substitute for reading the work order. Invalid JSON, duplicate keys, traversal, symlink escape, and mismatched or missing referenced files fail closed.
5. Regression tests use synthetic fixtures and cover normal retrieval, deduplication, identity/backlink failures, path and symlink escape, malformed metadata, unknown/stale planning decisions, deterministic content and hashes, and no partial output. Existing policy CI discovers and runs the new tests; Linux/MySQL and Windows reactor jobs remain required.
6. Documentation explains when to rebuild a packet after source changes and how to expand context when a dependency or conflict appears. TASK-0019 predecessor closeout records only independently verified PR and exact-merge-SHA CI facts.
7. Local checks, exact-final-head PR policy/Linux/Windows CI, trusted-main integration gates, protected merge, and actual merge-SHA push CI pass before TASK-0020 is claimed `POST_MERGE_VERIFIED`.
