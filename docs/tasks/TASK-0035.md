## Goal, authority and references

Support optional offline TOTP for privileged Accounts, without an internet service or
partially authenticated application sessions. Identity & Access owns all factor state.
Read D-151 and D-152 through the [planning index](../planning/INDEX.md), the
[module record](../modules/identity-access.md), [execution rules](../implementation/EXECUTION_RULES.md),
and [integration procedure](../implementation/GIT_INTEGRATION_AGENT.md).
PR #59 / TASK-0034 is independently post-merge verified before implementation.

## Scope and acceptance

- Add self enrollment for Accounts with identity:admin, requiring recent credential proof.
  Generate a random seed, expose it once through an owned clearable result, store only
  authenticated encryption bound to Account UUID, and confirm possession before enabling.
  Pending enrollment expires within ten minutes; re-enrollment cannot replace an active factor.
- Use RFC 6238 HMAC-SHA1, six digits, 30-second steps and a bounded one-step skew window.
  Reject reuse of a consumed step durably across restart and concurrent requests.
- Enrolled Accounts require password plus TOTP or one-use recovery code at ordinary
  form login and recent credential re-authentication. Missing/wrong/replayed factors share
  generic credential failure and existing persisted bounded lockout bookkeeping.
  No authorities/session registration/proof may be issued on password-only authentication.
- Generate ten independently random 128-bit recovery codes by default on confirmation or explicit
  replacement. Expose once, store only SHA-256 digests, consume atomically under the Account
  lock, and never treat recovery as password bypass. Replacement invalidates previous codes.
  D-151 operational configuration permits tighter skew (0-1), positive enrollment windows
  up to ten minutes and recovery counts of 2-10; invalid values fail startup.
- Support self disable and recovery-code replacement with recent full-factor proof, and
  authenticated administrative reset of another Account with identity:admin and recent proof.
  Reject administrative self reset; preserve password, identity, roles and enabled state.
  Password reset does not remove MFA. No anonymous recovery endpoint is introduced.
- MFA activation, disable, recovery replacement and administrative reset advance Account
  authentication generation, flush one fixed-context audit event and expire target sessions.
  Final registration and role-generation checks retain their race protection. Failure rolls
  back database/audit state; late commit failure may safely leave local sessions expired.
- Configure an external restricted 32-byte encryption-key file with no built-in key.
  Missing key permits existing unenrolled authentication but denies enrollment and enrolled
  authentication. Invalid configured keys fail startup with bounded diagnostics.
  Document protected key backup, clock synchronization, recovery handling and rollback.
- Adapt the existing Vaadin login to submit the optional factor in the same Spring/Vaadin
  form request, preserving existing CSRF behavior. Request factor buffers clear and never enter authenticated token,
  session, recent-proof marker, exception cause, audit, logs or ordinary configuration.
- Preserve released V1-V8 and frozen planning sources. Add V9 only for factor persistence;
  no identity/MFA/key/recovery seed, external provider, distributed infrastructure or dependency.

## Implementation and local verification - 2026-10-03

Identity-owned enrollment, confirmed activation, full-factor login/re-authentication,
one-use recovery replacement, self disable and other-Account administrative reset
are implemented. V9 is additive; encrypted seeds are Account-bound and recovery storage
holds only random-code digests. Controls preserve credentials/lifecycle/assignments,
advance generation, flush fixed UUID audit evidence and expire sessions. Request-only
factor buffers and owned display material clear; no MFA material enters authenticated
session/proof state. The login field stays in browser DOM and posts through the existing chain.

- Windows `.\mvnw.cmd -B clean verify`: 156 ordinary tests passed, including five MFA
  cryptography/policy tests and eight architecture tests.

  and 20 focused MySQL tests passed. Final full verification includes the final key-validation strengthening.
- Ubuntu `sh ./mvnw -B -Dmaven.repo.local=/opt/native-m2 -Pmysql-it clean verify`:
  156 ordinary and 139 real-MySQL tests passed, including all 15 MFA tests and V8-to-V9

- Both isolated build sources match all 165 implementation inputs. Verification artifacts

- Headless Edge against the packaged app verified rendered factor visibility, native
