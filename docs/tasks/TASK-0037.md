## Goal

Correct the Client Management reference/query transaction boundary so `ClientReferences` observes current committed Client Company/Site lifecycle state independently of any ambient caller transaction.

This corrective task closes the stale-snapshot gap discovered during fresh post-merge review of TASK-0036 / PR #61.

## Baseline and references

Reviewed baseline is `main` at `b7f834f2b1ea560f13d43b1c0589b46c336b16da`.

TASK-0036 was integrated through PR #61:

- final head `308ddbfb2a9506e9cdc6c08f388f524f5c673339`;

- merge `b7f834f2b1ea560f13d43b1c0589b46c336b16da`;
- exact-merge push run `37131439302`, successful policy/Linux/Windows.

Fresh review found that `JpaClientReferences` configures a read-only READ COMMITTED `TransactionTemplate` but leaves the default `PROPAGATION_REQUIRED`. When called inside an existing transaction, the query can therefore join the caller transaction instead of establishing the intended independent read boundary.

The unresolved PR #61 review thread on `JpaClientReferences` records this finding.

Relevant authority remains IMP-014 and TASK-0036's Client reference/query completion requirements.

## Scope and acceptance criteria

1. `ClientReferences.company(...)` and `ClientReferences.site(...)` must execute through an independent read transaction rather than joining an ambient caller transaction.

2. Configure the Client reference read transaction with `PROPAGATION_REQUIRES_NEW`, read-only operation, READ COMMITTED isolation, and the existing bounded timeout.

3. An ambient transaction with an older MySQL snapshot must not cause Client reference queries to return stale Company activity or stale Site effective activity after a separately committed Client lifecycle mutation.

4. Preserve the existing immutable projection contract: only stable public UUIDs, parent UUID, display name, lifecycle/effective-lifecycle state, and approved edit version information may cross the boundary.

5. Preserve bounded invalid-target and persistence-failure behavior. Infrastructure causes, SQL details, internal IDs, managed entities, repositories, lazy state, credentials, or request payloads must not escape.

6. Add deterministic unit coverage that verifies the intended propagation, read-only, isolation, and timeout transaction definition.

7. Add a real-MySQL regression reproducing the defect: establish an older ambient REPEATABLE READ snapshot, commit a relevant Client lifecycle change independently, then prove `ClientReferences` observes the newer committed state rather than the ambient snapshot.

8. The regression must cover the effective-activity decision relevant to later business consumers; a Site under a newly deactivated Company must resolve as not effectively active.

9. Preserve all TASK-0036 Client Company/Site lifecycle, authorization, audit, locking/version, migration, and architecture behavior.

10. No additional schema or production-data change is required.

## Implementation and verification - 2026-10-04

`JpaClientReferences` now explicitly uses REQUIRES_NEW while retaining read-only,
READ COMMITTED and the 15-second timeout. Existing unit checks assert all four
transaction-definition properties for Company and Site reads. Public projections,
validation/error boundaries, mutations, audit and schema are unchanged.

The real-MySQL regression establishes a REPEATABLE READ caller snapshot, waits for
an authenticated Company deactivation on a separate thread to commit, then proves
Company activity/version and Site effective activity are current through the reference
contract. Direct caller SQL remains stale before and after the reference reads;
Site identity/stored activity/version remain intact and only the mutation adds audit.
Removing only the propagation fix in the disposable Linux copy makes the regression
fail at the current-Company activity assertion (`expected false but was true`).
The fix was restored before final full verification. The negative-control command
selected only this integration method and deliberately did not run ordinary unit tests;
