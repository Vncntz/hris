# TASK-0009 — Shared identifier, money, and business-time primitives

Status: PLANNED — implementation gated until this planning PR merges and passes required post-merge `push` CI.

Parent implementation item: [IMP-006](../implementation/tasks/IMP-006.md)

## Goal

Establish the smallest neutral `shared-kernel` vocabulary for UUID-backed public identifiers, decimal money, local business dates, UTC instants, and explicit IANA business time zones. Keep types usable by later modules without moving domain ownership into the shared module.

## Non-goals

- No business entities, persistence mappings, API endpoints, schema or Flyway migrations.
- No employee/client-specific identifier scheme, payroll or statutory calculation, exchange-rate conversion, or tax rounding policy.
- No installation configuration/secrets framework (IMP-007), audit foundation (IMP-008), or domain-module integration merely to showcase the types.
- No system-default time zone, locale, or clock as a hidden business input.

## Affected modules and files

Implementation should be limited to `shared-kernel/src/main/java`, focused `shared-kernel/src/test/java` tests, and narrow module/developer documentation. Change its POM only for a demonstrated test need. Preserve the one-application Maven reactor; do not add dependencies from `shared-kernel` to the application or business modules. This planning PR contains documentation only.

## Implementation direction

1. Define a UUID-backed `PublicId` boundary with documented creation, parsing, canonical string form, invalid-input behavior, and value equality. Do not invent domain-specific IDs or expose persistence assumptions.
2. Define `Money` around `BigDecimal` with explicit scale, arithmetic, equality, and rounding behavior. Reject binary floating-point inputs. Keep legal/payroll precision and rounding rules outside the primitive unless an authoritative requirement is verified and separately scoped.
3. Define `BusinessDate` around `LocalDate` and `UtcInstant` around `Instant`, preserving their distinct meanings in APIs and formatting. Avoid implicit conversions from one to the other.
4. Define `BusinessTimeZone` around an explicit IANA `ZoneId` and a conversion API that requires the zone. D-123 names `Asia/Manila` as the Philippine installation default; selection and storage of the installation-level setting belong to later configuration work.
5. Make clock input injectable where time is read. A primitive must not call the host clock or default time zone to choose a business date. Keep the public surface small and dependency-free.

## Acceptance criteria

1. Public-ID construction and parse/format round trips are deterministic; malformed values fail clearly, and value equality is tested.
2. Money behavior uses `BigDecimal` only, documents representation and rounding contracts, rejects invalid inputs, and has tests for decimal edge cases and arithmetic; no statutory rule is invented.
3. Business dates and UTC instants remain distinct and round-trip without silently applying a host zone or locale.
4. Zone-dependent conversions take an explicit IANA zone and are tested around a date boundary and an offset transition in a zone that has one; host-default changes do not alter results.
5. `shared-kernel` contains only neutral primitives, has no application/business-module or infrastructure dependency, and no later IMP implementation appears in the diff.
6. Focused tests run through the checked-in Maven Wrapper as part of the ordinary reactor on Windows and Linux CI. Existing application smoke and MySQL migration tests retain their normal CI paths.
7. Documentation explains type meaning and usage boundaries. No secrets, customer data, migrations, or frozen planning-source changes are introduced.
