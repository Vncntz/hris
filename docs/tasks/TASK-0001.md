# TASK-0001 — Repository governance foundation

Status: COMPLETE (2026-09-29) — linked IMP-002 acceptance and verification complete

Parent implementation item: [IMP-002](../implementation/tasks/IMP-002.md)

## Goal

Establish the repository's agent contract, indexed documentation and ADR/task conventions, focused PR workflow, and verified protection of `main` under the approved solo-developer model.

## Non-goals

No application behavior, build changes, CI workflows, module-specific rules without a demonstrated need, invented ADRs, or retrospective IMP-001 cleanup.

## Affected modules

Repository governance only; no business or application module changes.

## Relevant decisions and documents

- Frozen Master Plan §§40–43 and 65.8; D-131, D-132, D-134, D-135, D-138, D-139, D-140.
- [Execution rules](../implementation/EXECUTION_RULES.md) and [implementation state](../implementation/IMPLEMENTATION_STATE.md).
- No approved ADR currently applies beyond the frozen decisions.

## Acceptance criteria

Use the authoritative [IMP-002 acceptance criteria](../implementation/tasks/IMP-002.md#acceptance-criteria). In particular, the documentation entry points and PR convention must be present, and the actual GitHub `main` protection and agent permissions must be enforced and verified before completion.

## Security and audit implications

Record effective repository safeguards without credentials. Keep real customer production data and secrets out of normal development, CI, and AI context. The human owner reviews PR evidence and makes the final merge decision; a second reviewer and separate non-admin agent credential are not required in the current phase.

## Required verification

Follow [IMP-002 required verification](../implementation/tasks/IMP-002.md#required-verification): check links and required fields, review the full local diff and scope, run `git diff --check`, and inspect remote protection. Do not use a destructive push as a protection test.

## Documentation

Create the root agent contract, `docs/README.md` and category indexes, task/ADR conventions, repository workflow, PR template, and verified completion or blocker evidence in the mutable implementation records.

## Migration and deployment

No database migration, production deployment, data conversion, or runtime change. The remote repository rule is an administrative setting; capture its previous state before changing it and verify the resulting state.

## Workflow follow-up (2026-09-29)

By explicit user request, the repository governance workflow now includes a repo-scoped Git integration skill for completed task branches and post-merge stack management. This is an operational handoff within IMP-002; it does not change application code, CI, or remote protection. The human owner still performs the final `main` merge.

## Later merge-authority supersession (2026-09-29)

The human-only merge statements above record the policy in force when TASK-0001 completed. A later explicit governance decision authorizes the dedicated [Git Integration Agent](../implementation/GIT_INTEGRATION_AGENT.md) to merge an eligible PR through protected `main` after independently verifying every gate. Historical acceptance and remote-protection evidence remain intact; branch-protection bypass remains prohibited.
