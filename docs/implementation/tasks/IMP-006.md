## Scope and acceptance direction

The first work order implements reusable value types or small helpers only in `shared-kernel`, with focused tests and documentation. Public identifiers must have a defined UUID-backed representation and reliable parse/format round trips. Money must use `BigDecimal` and explicit decimal behavior without floating-point arithmetic or implicit locale/rounding assumptions. Business dates must retain `LocalDate` meaning. Technical instants must retain UTC `Instant` meaning. Business-zone handling must use an explicit IANA `ZoneId`; the installation default is `Asia/Manila` under D-123, but host defaults cannot choose a zone silently. Tests must cover invalid inputs, equality/serialization boundaries, and date/instant conversion around zone transitions where relevant.

The primitives remain independent of Spring, JPA, Flyway, business modules, payroll rules, and installation configuration. Later owners wire the installation zone and an injectable clock/time service into application behavior. Add no cross-module dependency merely to demonstrate the primitives.

## Boundaries and dependencies

Do not add business aggregates, employee or customer identifiers with domain rules, money conversion or statutory rounding formulas, payroll calculations, persistence mappings, database schema, migrations, audit records, configuration/secrets framework, or business services. The one deployable application and existing module dependency direction remain unchanged. IMP-007 owns configuration conventions, IMP-008 audit, and later modules own domain use of these primitives.
