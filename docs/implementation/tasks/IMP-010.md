## Objective and authority

Turn the existing `tools/synthetic-data` structural placeholder into the smallest deterministic, versioned, scenario-based generator core that later domain and performance work can extend without using real customer data.

Relevant frozen authority includes Master Plan §7, §27, §65.1, D-132, D-136, D-137, D-143, D-144, D-145, D-146, D-148, and D-149.

D-145 requires dataset identity to include at least:

- generator version;
- named profile;
- deterministic random seed;
- scenario/options manifest.

It also requires named S/M/L/XL profiles, eventual XL support through at least 100,000 active employees, deterministic compatible regeneration, visibly fictional data, and no ordinary use of real customer production data.

No approved ADR applies.

Do not modify frozen planning sources.

## Current repository state

At IMP creation:

- `tools/synthetic-data` is already a Maven reactor module;
- its production source contains only a structural `package-info.java`;
- it has no generator implementation or tests;
- its POM currently adds no dependencies;
- `shared-kernel` already provides the neutral `PublicId` UUID primitive;
- the frozen scale envelope defines S as 500–2,000 active employees, M as 2,001–10,000, L as 10,001–30,000, and XL as 30,001–100,000;
- those scale figures are planning workload targets, not benchmark results.

## Scope and acceptance direction

IMP-010 establishes generator infrastructure only.

The focused implementation may:

- add `shared-kernel` as the only production project dependency where useful for neutral public identifiers;
- add JUnit as a test dependency using repository-managed versions;
- define an explicit generator version independent from the application SNAPSHOT version;
- define named S/M/L/XL baseline profiles;
- use the upper bound of each frozen active-employee scale tier as the initial baseline population target:
  - S: 2,000;
  - M: 10,000;
  - L: 30,000;
  - XL: 100,000;
- define a request containing profile, deterministic seed, scenario name, and canonical scenario options;
- define a stable dataset manifest containing the inputs required to identify the logical dataset;
- canonicalize manifest/options ordering and text encoding so equivalent requests have equivalent identity on Windows and Linux;
- derive deterministic fictional record identities from the dataset request without depending on wall-clock time, default locale, default timezone, host randomness, filesystem order, or process state;
- expose a lazy/streaming population-identity sequence so XL does not require materializing every generated record in memory;
- compute a deterministic dataset fingerprint/digest suitable for future benchmark metadata;
- establish a baseline scenario that proves the framework while remaining independent from unimplemented business-domain aggregates;
- provide deterministic golden tests, including an XL 100,000-record exercise;
- document how later module-owned scenario contributors may extend the generator.

Production generator code should remain JDK-centric and dependency-light.

## Boundaries

Do not implement:

- Worker, Employment, Applicant, Client, Deployment, Schedule, Attendance, Payroll, Billing, Compliance Rule Pack, or other future domain aggregates merely for synthetic generation;
- database persistence or a MySQL data loader;
- Flyway migrations;
- giant committed datasets or database dumps;
- a benchmark runner or approved performance baseline;
- production application runtime dependency on the synthetic-data tool;
- current Philippine statutory rates, tables, formulas, forms, or formats;
- customer-like government identifiers or copied customer schemas/data;
- random internet data acquisition;
- Faker-style external datasets whose reproducibility or provenance is unclear;
- a generalized plugin framework beyond what this skeleton actually needs.

Synthetic labels and identifiers must be visibly fictional.

Real customer production data remains prohibited.

## Determinism direction

Compatible execution of the same:

`generator version + profile + seed + scenario + canonical options`

must reproduce equivalent logical generator output.

Deterministic behavior must not depend on:

- `Random()` or another implicitly seeded random source;
- `UUID.randomUUID()`;
- current time;
- host timezone;
- host/default locale;
- platform-default charset;
- unordered-map iteration;
- filesystem traversal order.

Use explicit UTF-8 and a stable documented deterministic derivation algorithm.

A material incompatible change to deterministic generation must increment the generator version rather than silently changing the meaning of an existing dataset identity.

## Scale-profile direction

Initial baseline population targets use the upper boundary of each frozen scale tier so each named profile exercises its complete planning envelope:

- S — 2,000 active population identities;
- M — 10,000;
- L — 30,000;
- XL — 100,000.

These are workload-generation targets only.

`TARGET — NOT YET BENCHMARKED`

Generating 100,000 deterministic records successfully is not a claim that the HRIS application is performance-qualified for 100,000 active employees.

## Completion direction

TASK-0013 may close IMP-010 if it replaces the structural placeholder with:

- a versioned generator identity model;
- S/M/L/XL profiles;
- deterministic seed/scenario/options handling;
- canonical manifest/dataset identity;
- deterministic fictional record identities;
- an XL-capable lazy generation path;
- golden determinism and privacy-focused tests;
- documentation for later extension.

Completion of IMP-010 does not mean the full eventual D-145 business-domain dataset corpus exists. Domain-specific generators and performance scenarios are added only as their owning modules and benchmark work become available.
