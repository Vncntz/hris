## Objective and authority

Establish a simple, explicit runtime configuration model for supported Windows and Ubuntu installations, separating repository-safe defaults, environment-specific configuration, protected secrets, and development/test configuration.

The frozen Master Plan §65.1 backlog item IMP-007 and decisions D-023, D-024, D-028, D-029, D-035, D-108, D-130, D-150, and D-152 govern this item together with the execution rules, repository workflow, Git Integration Agent procedure, and implementation state. No approved ADR applies.

D-029 requires logical separation of application binaries, configuration/secrets, mutable state, logs, and database data. D-024 requires diagnostic configuration output to redact secrets. D-152 requires application credentials and recovery/private material to receive stronger protection than ordinary readable configuration.

## Scope and acceptance direction

Through focused work orders, IMP-007 may:

- define the supported Spring Boot externalized-configuration model;
- distinguish repository-safe defaults, development/test profiles, installation configuration, and protected secrets;
- document supported Windows and Ubuntu configuration locations consistent with D-029;
- define technical environment/property naming conventions where needed;
- add focused configuration loading/override tests;
- establish safe failure behavior for required technical configuration;
- document secret handling and future diagnostic-redaction requirements;
- strengthen repository ignore/example conventions where narrowly justified.

Prefer standard Spring Boot externalized-configuration mechanisms over custom loaders or external configuration infrastructure. Exact Spring Boot 4.1.1 behavior used by the implementation must be verified from current official documentation.

## Boundaries and dependencies

Do not implement:

- Agency/business configuration, which belongs to IMP-012;
- authentication, passwords, sessions, or authorization, which belong to IMP-009;
- append-only audit persistence, which belongs to IMP-008;
- production installer/service/firewall/MySQL provisioning;
- HTTPS certificate provisioning;
- backup/recovery;
- cloud secrets infrastructure;
- customer-specific configuration.

Do not add real credentials, production secrets, private keys, reusable passwords, customer data, or vendor signing material.

Do not introduce Vault, Kubernetes Secrets, required cloud configuration, or similar infrastructure without a separate approved requirement.

Do not create a committed production configuration file containing credentials or customer installation values.

Do not treat `.env` as a required production configuration mechanism merely because it is ignored by Git.

Windows and Ubuntu configuration conventions must remain compatible with D-029 without spreading hardcoded OS paths through business code.

No schema migration is expected.
