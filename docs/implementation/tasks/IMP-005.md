# IMP-005 — Flyway and global migration-order conventions

## Milestone and status

M0 — Engineering Foundation. P0. PLANNED; implementation waits for the TASK-0008 planning PR to merge and pass required post-merge CI.

Focused first work order: [TASK-0008](../../tasks/TASK-0008.md).

## Objective and authority

Introduce Flyway as the schema-migration foundation on the completed [IMP-004](IMP-004.md) real-MySQL/Testcontainers baseline. Establish one global ordering and immutable-history convention for migrations contributed by any module, with reproducible validation against disposable MySQL.

The frozen Master Plan §35 and §65.1 backlog item IMP-005, decisions D-143, D-144, and D-157, [execution rules](../EXECUTION_RULES.md), and [implementation state](../IMPLEMENTATION_STATE.md) govern this item. No approved ADR applies. D-157's production upgrade sequence is a later implementation concern; this item establishes only the migration foundation.

## Scope and acceptance direction

Through focused work orders, IMP-005 may add Flyway dependencies and configuration in the deployable application, a single authoritative migration location and global version-allocation convention, developer guidance for forward-only immutable released migrations, and real-MySQL tests of ordering, history, validation, and failure behavior. A minimal technical migration may prove those mechanics if it creates no business/domain table or customer data.

IMP-005 is complete when the first work order demonstrates that the application uses one ordered Flyway history, clean disposable MySQL applies the technical migration deterministically, repeat validation preserves history, and conflicting or changed migrations fail visibly. Tests must run through ordinary Maven Wrapper commands and applicable PR CI while Windows retains meaningful reactor coverage. Document how later modules obtain migration versions without separate competing histories. Preserve released migrations once published; corrections use later forward migrations.

## Boundaries and dependencies

Do not add business entities or tables just to demonstrate Flyway. Do not implement production upgrade orchestration or maintenance mode (IMP-060), backup/restore, installers or application deployment, customer-specific database configuration, later IMP scope, or downgrade as a normal rollback. Test data and credentials must be disposable and synthetic; no secrets or customer production data belong in source or CI. Later production recovery remains governed by D-157 and its own work orders.

## Completion evidence

Record actual PR, merge SHA, exact-head and post-merge CI, migration-test results, and any remaining limitations only after verified implementation. The task is complete when required post-merge `push` CI succeeds; its tracked closeout may be reconciled in the following planning PR.
