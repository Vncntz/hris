## Solo-Developer Governance Decision (2026-09-29)

- [DECISION — user] This repository is currently operated by one human developer and has no independent PR approver. IMP-002 must not require an artificial second account, a separate non-admin agent credential, or a second human reviewer merely to make the workflow operable.
- Normal changes to `main` still require a pull request. The classic protection rule must continue to apply to administrators and must continue to disallow force-push and branch deletion.
- The required approving-review count is 0 during the solo-developer phase. The human owner remains the approval authority in the operational sense: the owner reviews the PR and verification evidence and makes the deliberate final merge decision. An agent may prepare or update the branch/PR, but may not merge `main` or bypass protection.
- Agent access using the owner's credential does not create a separate trusted identity. Therefore IMP-002 relies on the repository workflow and explicit execution rules to prohibit agent-initiated merge/bypass/protection changes; a separate non-admin credential is not an acceptance criterion for this phase.
- IMP-003 owns CI creation. After stable named CI checks exist, `main` protection should require those checks before merge. If a genuine collaborator/reviewer is added later, required approving reviews may be increased from 0 to 1 as a governance hardening step.
- At the time of this decision, IMP-002 remained IN PROGRESS pending the 1-to-0 rule change, independent readback, local alignment, and closeout commit. The completion evidence below records the subsequent verification.
