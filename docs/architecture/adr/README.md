# Architecture decision records

No post-planning ADR has been approved. Frozen decisions currently live in the [Master Software Plan](../../planning/MASTER_SOFTWARE_PLAN.md); the [planning state](../../planning/FINAL_PLANNING_STATE.md) records the handoff.

Allocate the next unused four-digit `ADR-####` ID. Keep the ID stable. An ADR records title, status (proposed, accepted, rejected, or superseded), date, context, decision, consequences, and links to affected tasks and related ADRs. Approval must be explicit; a proposed ADR is not an accepted architecture change.

Preserve accepted records. When a decision changes, write a new ADR that links to the old one, and mark the old record superseded with a link to the new one. Do not rewrite accepted history to conceal the change. Keep this index updated as records are added.
