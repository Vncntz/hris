# Platform/Operations Agency configuration

Platform/Operations owns one Agency configuration root for an installation and database. The global V4 migration creates an empty `agency_configuration` table. Its primary key is constrained to the fixed value `1`, so concurrent or direct writes cannot create a second logical Agency. The separately stored UUID is the stable public identifier; the fixed key is internal and never returned as business identity.

`AgencyConfigurationService` exposes `initialize(displayName, businessTimeZone, actorId)`, `current()`, and `update(displayName, businessTimeZone, expectedVersion, actorId)`. These operations return an immutable `AgencyConfiguration` projection, not the JPA entity or repository. Initialization is explicit and once only. Names are stripped, nonblank, at most 200 Java characters, and reject control characters. The name is an operator-facing label, not a legal or statutory registration claim. The caller must supply an explicit IANA `BusinessTimeZone`; `Asia/Manila` is the Philippine reference value, never inferred from the machine. No production Agency row is seeded.

Creation and material update use an injected `Clock`, truncate to MySQL microsecond precision, and store technical times as UTC wall times in `DATETIME(6)`. Update preserves the public UUID and creation time, checks the caller's expected version, and uses JPA optimistic locking. An unchanged update leaves the version and audit history alone. Successful initialization and material update append `AGENCY_CONFIGURATION_INITIALIZED` or `AGENCY_CONFIGURATION_UPDATED` in the same transaction. The audit event contains the actor UUID, action, target type, and Agency UUID; it omits the display name and zone. A surrounding rollback removes both the Agency change and audit event.

The caller supplies an actor `PublicId`; no user interface or HTTP mutation endpoint exists here. IMP-013 will connect authenticated current-actor and administrative authorization to an operator-facing setup flow. This service does not depend on Identity & Access. Legal identifiers, tax or permit details, Client/Site, general settings, and multi-agency tenancy are outside this root.
